# 소액 실거래 시작 절차

검증은 끝났다. 남은 건 **백테스트와 다른 것이 돌아가고 있지 않은지**
확인하면서 천천히 키우는 것뿐이다. 순서대로 하면 된다.

---

## 0. 먼저 알아야 할 숫자

백테스트 8.9년, 지금 기본값 그대로 (진입당 1.5%·2배·총노출 60%·
차단기 20%·복리·왕복 0.40%·청산 저가판정·볼린저 상단 목표청산):

| | 전체 2017~2026 | 홀드아웃 2024~ |
|---|---|---|
| 전체 | 3.14배 (연복리 14%) | 2.00배 (연복리 33%) |
| **최대낙폭** | **21.6%** | **3.7%** |
| 승률 | 81% | 88% |
| 1년 구간 손실 확률 | 29% | 0% |

**세 해 중 한 해는 손실로 끝난다.** 견딜 수 있는 금액만 넣어라.

**숏(주봉)·상승 다이버전스(일봉)도 이제 봇에 들어 있다.** 셋을 다
굴리면 전체 21.5배·낙폭 21.6%·1년 손실확률 1~5%다(위 표는 롱만
돌렸을 때). 장부는 `python ml/report.py` 로 본다.

  모듈        시간봉   진입당    배율   연 거래   승률
  과매도 롱    4시간봉   1.5%     2배    204건    82%
  주봉 숏      주봉      40%      1배    2.6건    83%
  상승 다이버   일봉      40%      1배    7.4건    62%

숏·다이버는 일봉을 하루 한 번만 보고 판정한다. 4시간봉 롱은 5분마다
돈다. 숏은 주가 닫히는 **월요일에만** 주문을 내고, 그날 봇이 안
돌았으면 그 거래는 거른다 — 틀린 가격에 들어가는 것보다 낫다.

아직 실거래로 검증한 적이 없다. 위 숫자는 전부 백테스트다.

## 1. 바이빗 API 키 만들기

1. 바이빗 → API → 새 키 생성
2. **출금 권한은 반드시 끈다.** 이 봇은 조회·주문만 필요하다
3. 가능하면 접속 IP를 봇이 돌 PC의 IP로 고정한다
4. 권한: `읽기` + `거래(Trade)` 만

**키를 채팅·깃·로그 어디에도 붙여넣지 마라.** `.env` 파일에만 넣는다
(이미 `.gitignore`에 등록돼 있다).

```
# 저장소 루트에 .env 파일 생성
BYBIT_API_KEY=여기에_키
BYBIT_API_SECRET=여기에_시크릿
```

## 2. 자본 점검 — 얼마부터 되나

1차 진입액은 **자본의 0.9%** 다 (자본 × per_trade 1.5% × 배율 2배 × 1차비율 30%).
이게 거래소 최소주문량보다 작으면 그 종목은 신호가 떠도 건너뛴다.

봇이 시작할 때 자동으로 알려준다:

```
자본 300.00 USDT · 1차 진입액 9.00 USDT (자본의 3.0%)
거래 가능 종목 35/42종
⚠️  최소주문량 미달로 건너뛸 종목 7종: BTCUSDT, ETHUSDT, ...
   42종 전부를 거래하려면 자본 약 3,400 USDT 필요
```

**BTC가 보통 가장 비싸다** (최소 0.001 BTC ≈ 100 USDT 주문).
소액으로 시작하면 BTC·ETH는 자동으로 빠지고 알트만 거래하게 된다.

백테스트는 42종 전부에서 신호를 받았다. 종목이 빠지면 검증한 것과
다른 것을 굴리는 셈이니, 몇 종이 빠졌는지 매번 확인해라.

## 3. 모의로 먼저 돌린다 (최소 1주)

```bash
python -m bot.oversold.executor
```

기본이 모의(dry-run)다. 실제 주문은 안 나간다. 확인할 것:

- [ ] 자본 점검에서 거래 가능 종목이 몇 종인지
- [ ] 4시간마다 신호를 제대로 잡는지
- [ ] 신호가 뜬 종목이 백테스트 신호와 같은지
- [ ] 로그에 이상한 오류가 없는지

한 번만 점검하고 끝내려면 `--once` 를 붙인다.

캔들을 저장해두면 나중에 백테스트와 대조할 수 있다:

```bash
python -m bot.oversold.executor --once --dump-candles
```

## 4. 실거래 시작

```bash
python -m bot.oversold.executor --live
```

`START` 를 입력해야만 시작된다. 시작 전에 낙폭 경고를 다시 보여준다.

**시작 금액**: 위 자본 점검을 보고 정한다. 너무 적으면 거래 가능
종목이 몇 개 안 남아 백테스트와 완전히 달라진다. 300~500 USDT면
알트 대부분은 거래되고, BTC·ETH는 빠진다.

**첫 달은 절대 늘리지 마라.** 실거래 체결가가 백테스트와 얼마나
다른지 볼 표본을 모으는 기간이다.

## 5. 봇이 계속 떠 있어야 한다

이 규칙은 **목표가에 파는 게 아니라 20봉(80시간) 뒤에 판다.**
봇이 죽어 있으면 청산이 안 된다.

상태는 `bot/oversold/state.json` 에 저장되고, 재시작하면 밀린 청산부터
처리한다. 그래도 장시간 꺼두지 마라.

```bash
# 백그라운드로 계속 돌리기 (리눅스/맥)
nohup python -m bot.oversold.executor --live > bot.log 2>&1 &

# systemd 등 사람이 없는 환경이면 (deploy/README.md 참고)
#   OS_CONFIRM_LIVE=START python -m bot.oversold.executor --live-nonint
# 플래그와 환경변수가 둘 다 있어야만 실거래가 켜진다.

# 로그 보기
tail -f bot.log
```

전량 청산하고 멈추려면:

```bash
python -m bot.oversold.executor --live --close-all
```

## 6. 손절이 어떻게 걸리나

| | |
|---|---|
| 손절가 | **평단 대비 −40%** (`strategy.STOP_PCT`) |
| 거는 방식 | 진입 주문에 `stopLoss`를 실어 **거래소 서버에** 올린다 |
| 봇이 죽으면 | 손절은 거래소에 있으므로 **그대로 작동한다** |
| 2차 매수 후 | 평단이 바뀌므로 손절가도 새 평단 기준으로 다시 건다 |
| 매 점검마다 | 거래소 손절가를 읽어 확인하고, 없으면 **다시 건다** |

배율 2배에서 강제청산선은 −49.5%다. 손절 −40%가 **먼저** 걸리므로
정상 동작에서는 강제청산까지 가지 않는다. 백테스트에서 8.8년 동안
손절은 1,923건 중 2.5%만 걸렸고 강제청산은 9건이었다.

**손절이 없는 줄 모르고 도는 것이 이 봇에서 가장 크게 잃는 경로다.**
그래서 매 점검(5분)마다 거래소 쪽 손절가를 읽어 대조한다. 0.5% 이상
어긋나거나 비어 있으면 로그에 `⚠️ ... 손절이 없음` 을 찍고 다시 건다.
이 줄이 자주 보이면 뭔가 잘못된 것이니 멈추고 확인해라.

## 안전장치 요약

| 장치 | 기본값 | 환경변수 |
|---|---|---|
| 배율 | 2배 | `OS_LEVERAGE` |
| 거래당 전체물량 (롱) | 자본의 1.5% (최대 40종 동시) | `OS_PER_TRADE` |
| 거래당 전체물량 (숏) | 자본의 40%, 배율 1배 | `OS_PER_TRADE_SHORT` |
| 거래당 전체물량 (다이버) | 자본의 40%, 배율 1배 | `OS_PER_TRADE_DIV` |
| 숏 동시 진입 | 하루 1건 (신호는 월요일에만 뜬다) | `modules.SHORT_MAX_CONCURRENT` |
| 국면 스위치 | `--regime bull` 이면 숏을 끈다 | `state/regime.json` |
| 총노출 상한 | 자본의 60% × 배율 | `OS_MAX_GROSS` |
| 일일 손실 한도 | 5% | `OS_DAILY_LOSS` |
| 낙폭 차단기 | 20% (30일 뒤 자동 재개) | `OS_MAX_DRAWDOWN` |
| 차단 후 재개 | 30일 | `OS_HALT_COOLDOWN_DAYS` |
| 최소 자본 | 50 USDT 미만이면 진입 중단 | `OS_MIN_EQUITY` |
| 점검 주기 | 300초 | `OS_POLL_SECONDS` |
| 목표 청산 | 볼린저 상단(20봉·1.5σ) 지정가, 봉마다 갱신 | `strategy.BB_K` |
| 손절 | 평단 대비 −40%, 거래소 서버에 등록 | `strategy.STOP_PCT` |
| 손절 감시 | 매 점검마다 대조하고 없으면 다시 건다 | (강제) |
| 격리마진 | 진입 직전 전환, 실패하면 그 종목 건너뜀 | (강제) |

**차단기가 총낙폭을 20%로 묶어주지 않는다.** 발동할 때 고점을 현재
자본으로 다시 잡기 때문에 −20%가 겹쳐 쌓인다. 지금 설정의 실제 누적
낙폭은 21.6%다 — 진입당 물량을 5%에서 1.5%로 줄이고 총노출을 60%로
묶은 결과이지, 차단기가 막아준 게 아니다.

## 문제가 생기면

| 증상 | 원인 / 조치 |
|---|---|
| 신호가 떠도 진입을 안 한다 | 자본 점검에서 최소주문량 미달인지 확인 |
| "격리마진 전환 실패" | 바이빗에서 해당 종목에 이미 교차마진 포지션이 있는지 확인 |
| "총노출 상한 초과로 건너뜀" | 정상이다. 20종이 다 찼거나 2차 예약분이 자리를 잡고 있다 |
| 봇이 죽었다 | 재시작하면 상태 파일에서 복구한다. 밀린 청산부터 처리한다 |
| 낙폭이 25%를 넘었다 | 차단기가 신규 진입만 막는다. 보유분은 그대로 간다 |
